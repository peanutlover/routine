# 웨이트트레이닝 루틴

데드리프트·스쿼트 5% 증량과 디로딩, 보조 운동의 횟수·무게 진행을 훈련방식(바벨·덤벨·머신·밴드 등)에 맞춰 자동으로 계산하는 주간 운동 루틴 웹앱.
`index.html` 하나로 동작하고, 기록은 각자 휴대폰 브라우저에 저장된다.

## 파일

| 파일 | 역할 |
| --- | --- |
| `index.html` | 앱 전체 (빌드 결과물, 이 파일을 올린다) |
| `manifest.webmanifest`, `sw.js`, `icon-*.png`, `apple-touch-icon.png` | 홈 화면 앱·오프라인용 |
| `src/logic.js` | 증량·디로딩·실패 처리·달력 계산 (순수 함수) |
| `src/app.js`, `src/style.css`, `src/body.html` | 화면 |
| `test/logic.test.js` | 로직 테스트 |

수정 후에는 `node build.mjs`로 `index.html`을 다시 만들고, `node --test test/logic.test.js`로 확인한다.

## 이미 하던 루틴 이어가기

처음 열었을 때 안내의 **이어서 시작**(또는 이번 주 화면에서 지난 날의 **이 날 운동했어요 · 이어서 시작**, 설정 → 시작 지점)을 누른다.
그 날 운동이 몇 세션의 몇 번째였는지, 하체 단계와 무게·횟수를 넣으면 그 지점부터 계산을 이어간다.
세션 번호를 바꾸면 지금 설정에서 모두 성공했다고 보고 무게·횟수를 미리 채운다. 그 뒤 지난 날들은 날짜순으로 하나씩 기록한다.

## 운동 고르기 · 훈련방식

처음 열면 데드리프트 날·스쿼트 날에 할 운동을 빼거나 더할 수 있다(이미 시작했으면 설정 → 보조 운동에서 추가·삭제).
종목마다 훈련방식을 고른다.

| 훈련방식 | 증량 |
| --- | --- |
| 바벨 · 머신(원판) · 원판 여러 장 | %·kg으로 올리고 5kg 단위 원판 + 2.5kg·경량원판 조합을 안내 |
| 머신(무게추) | %·kg으로 올리고, 종목마다 넣은 무게추 단계에 꽂을 칸 + 위에 올릴 원판을 안내 |
| 덤벨 · 일체형 바벨 · 원판 한 장 | 설정 → 장비에 넣은 무게 중 다음 무게로 |
| 고무밴드 | 증량 없음. 그날 쓴 밴드와 성공·실패만 기록 |

데드리프트·스쿼트는 설정 → 하체 메인에서 종목마다 **5%씩** 또는 **5kg씩** 올릴지 고른다(실패·오래 쉬어 낮출 때도 같은 폭). 바벨·머신·원판 여러 장 보조 종목은 종목마다 증량 방식(%·kg)과 값을 고른다.
기록 중에 바꾸면 진행 중인 세션은 그대로 하고 다음 세션부터 앞 세션 무게에서 새 방식으로 오르내린다(하체는 `main.ichg`에 `{no, id, inc}`로 남는다). 아직 시작 전인 세션이면 그 세션부터.

진행 방식은 **무게 고정**(무게는 그대로, 횟수 단계 예: 3·4·5회를 올라가고 끝을 성공하면 다음 세션에 한 칸 증량) 또는 **횟수 고정**(횟수는 그대로, 무게 3단계를 올라가고 끝나면 2단계 무게부터 새 묶음). 하체도 둘 중 고를 수 있다.
기록이 있는 종목의 훈련방식이나 무게를 바꾸면 그 종목의 다음 세션부터 새 무게로 시작하고 지난 기록은 그대로 남는다(예: OHP 일체형 바벨 → 바벨).
세션 중간에 추가한 종목은 그 세션의 남은 차례부터 한다.

## 기록 규칙

- 기록할 때 한 종목만 골라도 저장된다. 고르지 않은 종목은 안 한 것으로 보고 다음 같은 날(데드 날·스쿼트 날)로 밀린다. 하체를 안 했으면 다음 날도 같은 하체 날이다.
- 상체·팔은 자기 하체 날에만 하고 하체보다 앞서지 않는다. 밀린 종목은 지난 세션 몫부터 차례로 하고, 하체를 따라가느라 쉬는 날은 휴식으로 본다.
- 세션(운동 6회)을 하는 동안 2일 이상 쉬었다면 세션 뒤 정식 휴식은 건너뛴다.
- 휴식일에도 운동했다면 기록할 수 있고, 운동한 날로 계산한다.
- 기록마다 그날의 상태(단계·무게·횟수·세트)를 함께 남긴다. 진행 방식·횟수 단계·횟수·세트·장비 무게·증량 값을 중간에 바꿔도 이미 한 기록은 그대로 보이고, 지금 무게와 성공·실패에서 바뀐 설정으로 다음을 계산한다. 진행 방식을 바꾸면 마지막 세션을 성공했을 때 다음 세션이 한 칸 무거운 무게가 되도록 이어 간다.
- 데드리프트 시작 무게를 바꾸면 지금 무게도 같은 비율로 바뀐다(지난 기록은 그대로). 지난 날 결과를 고치면 그 뒤 기록은 지금 설정으로 다시 계산한다. 시작 지점을 옮기면 모든 기록을 다시 계산한다.

## 오래 쉬면 처음부터

- 한 종목을 5일 이상 쉬면(그 종목을 마지막으로 한 다음 날부터, 다시 하는 날 전날까지 센 날 수) 성공·실패와 상관없이 그 종목의 진행 중인 세션을 처음부터 다시 하고 한 단계 낮춘다. 10일 이상이면 한 단계 더(한 번 쉬는 동안 두 단계까지). 한 단계는 실패했을 때와 같다: 횟수 고정은 무게 한 단계(−5%, 가진 덤벨 한 칸 등), 무게 고정은 횟수 한 단계.
- 예: 세션 2(2단계)에서 스쿼트를 2번 하고 3번째를 10일 넘게 못 했으면 2번 한 것은 지우고 세션 2를 데드리프트부터 다시 하는데, 두 단계 낮춘 −1단계(1단계 바로 아래 무게)부터다. 묶음을 채우려면 −1·1·2·3·4단계 순서로 올라간다. 세션마다 실패가 있으면 다음 세션에 한 단계 낮추는 규칙은 그대로.
- 하체는 데드리프트·스쿼트 중 더 오래 쉰 쪽으로 세고, 하체 세션을 처음부터 다시 하면 그 세션의 상체·팔도 처음부터 한다(무게는 종목마다 쉰 날 수대로 따로). 다시 시작한 날 하체를 하면 그 쉬는 기간은 끝난 것으로 본다(다음 날 스쿼트가 또 낮아지지 않는다).
- 상체·팔이 쉬는 하체 마지막 단계 세션은 쉬는 날로 세지 않는다. 고무밴드는 낮추지 않는다. 한 번도 하지 않은 종목은 세지 않는다.
- 오늘 할 종목을 쉰 지 3일째·4일째 되는 날에는 이번 주 화면 위에 "이틀 더 / 오늘 하루 더 쉬면 처음부터"를, 처음부터 다시 하게 된 날에는 그 사실을 알려준다.
- 이 규칙은 이 판을 처음 연 날(그날 이미 기록했으면 다음 날)부터 한 운동에 적용한다(설정의 `restFrom`). 그 전에 한 기록은 그대로다.

## 기록 그래프

그래프 탭에서 실제로 한 기록만 날짜별로 그린다. **한눈에**는 모든 종목을 겹쳐 보여주는데, 종목마다 처음 기록을 맨 아래·가장 많이 오른 때를 맨 위로 맞춰 y축 크기는 무시한다(누르면 실제 증량 %와 무게). **종목별**은 종목마다 kg 그래프. 속 빈 점은 실패한 날.

## 휴식 타이머

오늘 카드의 **휴식 타이머**를 누르면 오늘 할 종목마다 타이머가 따로 나온다. 순서는 자유. 종목별 휴식 시간은 처음 한 번 정하면 설정에 저장되고, 세트를 마칠 때마다 **휴식 시작**을 누르면 줄어든다. 휴식이 "세트 수 − 1"번 끝나면 그 종목은 완료. 끝나는 시각을 저장하므로 화면이 꺼졌다 켜져도 남은 시간이 맞고, 끝나면 소리·진동(지원하는 기기)으로 알린다.

## 알림 (앱을 닫아도)

설정 → **알림 켜기**를 누르고 허용하면, 다른 앱을 쓰거나 화면이 꺼져 있어도 휴식 타이머가 끝날 때 알림이 온다("스쿼트 휴식 끝 · 2세트 시작 · 35kg × 5회"). 운동을 쉰 지 3·4일째(10일 규칙은 8·9일째) 되는 날 아침 9시에도 알려준다. 기기마다 따로 켠다.

- 아이폰: Safari → 공유 → 홈 화면에 추가 → 그 아이콘으로 연 앱에서만 켤 수 있다(iOS 16.4 이상).
- 안드로이드: Chrome·삼성 인터넷 등에서 바로 켤 수 있다(홈 화면에 추가하면 더 편하다). 배터리 절약에서 브라우저를 제한하면 늦게 올 수 있다.
- Claude 링크에서는 쓸 수 없다. 앱을 보고 있는 채로 타이머가 끝나면 앱이 소리로 알리고 알림은 보내지 않는다.

앱 자체는 서버가 없어서, 알림은 `push/`의 작은 서버(Cloudflare Workers 무료)가 정해진 시각에 웹 푸시로 보낸다. 앱이 보낼 시각·내용을 맡기면 기기마다 Durable Object 하나에 넣어 두고 그 시각에 보낸다.

| 파일 | 역할 |
| --- | --- |
| `push/src/index.js` | 알림 서버: 맡기기·취소·보내기 (`POST /api`) |
| `push/src/webpush.js` | 웹 푸시 암호화(RFC 8291)·서명(VAPID) |
| `push/wrangler.toml` | 배포 설정, 공개키 `VAPID_PUBLIC`, 허용할 앱 주소 `ALLOW_ORIGINS` |

다시 배포하려면 `cd push && npx wrangler deploy`. 서명 비밀키는 Cloudflare에만 있다(`npx wrangler secret put VAPID_PRIVATE`). 키를 새로 만들면 `wrangler.toml`과 `src/app.js`의 `VAPID` 공개키를 같이 바꾸고, 각 기기에서 알림을 다시 켜야 한다. 시험: `node --test push/test/webpush.test.mjs`(RFC 8291 예제와 같은지), `npx wrangler dev` 띄운 뒤 `node push/test/local.mjs`(가짜 푸시 서비스로 끝까지).

## 다른 사람과 공유하기 (무료, 앱스토어 없이)

1. GitHub에 저장소를 만들고 이 폴더를 올린다 (`src/`, `test/`는 빼도 된다).
2. 저장소 Settings → Pages → Branch를 `main` / `root`로 저장한다.
3. 1~2분 뒤 생기는 `https://<아이디>.github.io/<저장소>/` 주소를 공유한다.

Netlify, Cloudflare Pages처럼 정적 파일을 올리는 다른 서비스도 똑같이 쓸 수 있다. 서비스 워커가 동작하려면 https 주소여야 한다.

휴대폰에서 파일을 내려받아 파일 앱·메신저 미리보기로 열면 스크립트가 돌지 않아 앱이 동작하지 않는다(안내 화면만 보인다). 반드시 웹 주소로 연다.

## 아이폰에 설치

Safari로 주소를 연다 → 공유 버튼 → **홈 화면에 추가**. 아이콘이 생기고 전체 화면 앱처럼 열린다.
기록은 그 기기에만 저장되므로 설정 → 데이터 → **백업 복사**로 가끔 백업해 둔다.
